# Виртуальная лаборатория — кратко для Кирилла

Платформа: **Go** (API), **PostgreSQL**, **React** (вход в браузере). ВМ студента — отдельный **Docker-контейнер** с **noVNC** (рабочий стол в браузере), образ с **Geany**.

---

## Что нужно

**Docker** + **Docker Compose** v2. Всё остальное поднимается само.

---

## Как запустить у себя

```bash
make up
```

Эта команда:

1. Собирает образ лаборатории `edu-lab-lab-vnc:geany` (LXDE + noVNC + Geany).
2. Поднимает БД и приложение с нужными переменными (`LAB_IMAGE` и т.д.).

Открой в браузере: **http://localhost:9000**

Остановить только compose-сервисы:

```bash
docker compose down
```

**Важно:** контейнеры ВМ студентов называются `lab_<student_id>` — они **не** входят в compose. После `docker compose down` они могут **продолжать работать**. Чтобы убрать все лаборатории:

```bash
docker ps --filter name=lab_
docker stop $(docker ps -q --filter name=lab_) 2>/dev/null; docker rm $(docker ps -aq --filter name=lab_) 2>/dev/null
```

(или останови ВМ через интерфейс / логику приложения, когда платформа снова запущена.)

## Вход (демо)

После первого старта с БД создаются пользователи:

| Кто     | Логин (student_id) | Пароль   |
|---------|--------------------|----------|
| Студент | `student1`         | `student` |
| Админ   | `admin`            | `admin`   |

---

## Как пользоваться: студент

1. Войти как `student1` / `student`.
2. **Запросить ВМ** по шаблону (кнопка, описание обязательно).
3. Дождаться, пока **админ одобрит** заявку.
4. В блоке «Активная ВМ» открыть **ссылку noVNC**, пароль VNC указан на странице. На столе — **Geany** (если образ собран через `make up`).
5. Пока открыта **вкладка с кабинетом**, раз в ~2 мин уходит «присутствие». Если **не заходить в кабинет дольше** времени из `SESSION_IDLE_MINUTES` (по умолчанию **60** минут), ВМ **остановится автоматически** (бэкап + остановка контейнера).
6. Кнопка **«Выйти»** — тоже останавливает ВМ у студента (если была активная сессия) и делает бэкап.

Удаление ВМ — только через **заявку на удаление** и одобрение админа (не из настроек студента напрямую).

---

## Как пользоваться: админ

1. Войти как `admin` / `admin`.
2. В панели — список заявок, фильтры по статусу/типу.
3. **Одобрить** заявку на **создание** → поднимется контейнер, студент увидит ссылку.
4. **Одобрить** заявку на **удаление** → бэкап, контейнер снимается, сессия закрывается.
5. **Отклонить** — с комментарием для студента.

## Переменные окружения (если надо подкрутить)

Задаются в `.env`, в shell или в `docker-compose.yaml`:

| Переменная | Зачем |
|------------|--------|
| `LAB_IMAGE` | Образ ВМ. В compose уже по умолчанию `edu-lab-lab-vnc:geany`. |
| `SERVER_IP` | В ссылках на noVNC вместо `localhost` — IP сервера в LAN. |
| `SESSION_IDLE_MINUTES` | Через сколько минут **без открытого кабинета** автоматически гасится ВМ (по умолчанию 60). |
| `JWT_SECRET` | Секрет JWT; в проде сменить обязательно. |

## Структура (куда смотреть в коде)

- `cmd/edu-lab` — точка входа, `-server` поднимает HTTP.
- `internal/server` — маршруты, заявки, сессии, `/api/auth/logout`, `/api/session/ping`.
- `internal/lab` — `docker run` / stop, имена контейнеров `lab_<id>`.
- `internal/idle` — автоостановка по простою (пинг с дашборда).
- `web/` — React (Vite). При `docker compose build` фронт собирается внутри корневого `Dockerfile`. Локально для отладки UI: `cd web && npm install && npm run build`.
- `docker/lab-vnc/` — Dockerfile образа рабочего стола.

## Безопасность (коротко)

Сокет Docker в контейнере платформы — это по сути root на хосте; для продакшена — свои пароли, `JWT_SECRET`, ограничение сети.
